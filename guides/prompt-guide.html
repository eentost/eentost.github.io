AI 활용 가이드

상황에 맞는 AI 프롬프트를 만드는 방법

프롬프트는 작업 명세서처럼 작성하는 편이 유용합니다. 멋진 역할 이름보다 작업의 목적, 제공 가능한 근거, 피해야 할 실수, 원하는 결과를 명확히 하는 것이 중요합니다.

1. 먼저 원하는 행동을 구체화하세요

“메일 써줘”보다 “고객에게 배송 지연 사실을 알리되 아직 확인되지 않은 발송일을 확정적으로 말하지 않는 메일을 써줘”가 더 분명합니다. 누구에게, 왜, 무엇을 요청하는지를 먼저 정하세요.

2. 근거와 가정을 구별하세요

“문의 처리 시간이 길다”는 문제 진술입니다. “지난주 접수 200건 중 30건이 48시간을 넘었다”는 수치입니다. 실제 데이터가 없다면 AI에게 임의의 숫자를 만들지 말고 필요한 데이터를 정리하도록 지시하세요.

3. 제약조건을 빠뜨리지 마세요

업무 이메일은 금지 표현, 데이터 분석은 모집단과 기간, 코드 개선은 반드시 유지할 API와 회귀 조건을 명시하세요. 회의 정리에서는 없는 담당자나 기한을 발명하지 않도록 요구합니다.

4. 결과 형식을 작업에 맞추세요

대안 비교에는 표, 반복 작업에는 체크리스트, 일정 계획에는 단계별 절차, 독자 안내에는 문단이 유용합니다. 모든 답을 똑같은 형식으로 출력할 필요는 없습니다.

5. 생성된 답을 검증하세요

AI가 그럴듯하게 제시한 숫자·출처·법적 기준도 검증 전에는 사실이 아닙니다. 특히 실제 자료가 필요한 업무에서는 원문과 비교해야 합니다. 이 생성기는 외부 AI를 호출하지 않고 요청문만 만들므로 정확성을 자동 검증하지 않습니다.

실무 사례

회의 요약: 결정사항과 제안·미결을 분리하고, 담당자가 없다면 '미정'으로 표시하도록 요청합니다.

면접 준비: 실제 경험만 입력해 사실 기반 답변을 연습하고, 겪지 않은 성과는 만들지 않도록 합니다.

코드 수정: 관측된 증상, 재현 절차, 기존 기능 보존 조건, 테스트 기준을 함께 적고 실행하지 않은 검증을 완료했다고 표현하지 않게 합니다.

개인정보 주의

브라우저에서 입력한 내용은 이 도구 자체의 서버로 전송되지 않습니다. 다만 생성된 문장을 다른 AI에 붙여 넣으면 해당 AI 제공자의 데이터 처리 정책이 적용됩니다. 고객 정보, 비밀번호, 계약 기밀은 입력 전 제거하세요.
