AI 탐지 모델 평가의 일곱 가지 함정

2026-10-28 · 평가 설계 가이드

‘정확도 99%’라는 수치만으로는 현장 운영 가능성을 판단하기 어렵습니다. 먼저 무엇을 한 건으로 세었는지, 정답은 누가 만들었는지, 학습 때 본 사례와 얼마나 독립적인지 확인해야 합니다.

1. 같은 사건을 여러 행으로 세기

로그 줄 수, 요청 수, 세션 수, 공격 시도 수, 사건 수는 서로 다릅니다. 로그 100줄이 하나의 공격 사건일 수 있습니다. 평가 단위를 ‘이벤트’로 정했다면 보고서에서도 끝까지 이벤트 기준을 유지하고 사건 기준 지표는 별도로 계산합니다.

2. 학습과 시험에 사실상 같은 자료가 섞이기

하나의 악성코드 계열에서 변형한 샘플이나 하나의 세션에서 분리한 요청을 무작위 분할하면 모델이 이전에 본 특징을 알아볼 수 있습니다. 파일 해시뿐 아니라 계열·수집 시기·조직·세션·호스트로 분할 누수를 점검합니다.

3. 정답 생성 규칙이 모호하기

룰이 경보를 냈다는 이유만으로 악성 정답을 주면, 학습 모델은 룰의 오류를 배울 수 있습니다. 확정/추론/미확인 라벨을 분리하고 라벨의 근거 자료·검토자·충돌 해결 정책을 남겨야 합니다.

4. 정확도만 제시하기

실제 악성이 0.1%라면 모든 입력을 정상으로 분류해도 정확도는 99.9%입니다. 반드시 TP·FP·TN·FN을 제공하고 precision, recall, FPR과 운영 경보량을 함께 보고합니다. 경보량 계산기에서 기저율 영향을 직접 확인할 수 있습니다.

5. 임계값을 시험셋에 맞추기

최종 시험셋을 반복 확인해 가장 좋아 보이는 임계값을 고르면 그 시험셋은 더 이상 독립 평가 자료가 아닙니다. 튜닝용 검증셋과 최종 잠금 시험셋을 분리합니다.

6. 미탐과 분석 불가를 숨기기

파싱 실패, 누락 필드, 모델 입력 불가, 시간 초과를 평가에서 제외하면 실제 품질이 과대평가됩니다. 처리 가능 비율과 평가 제외 건수를 원래 모집단 기준으로 보고합니다.

7. 기관별 차이를 무시하기

한 기관의 프록시·접근 패턴에서 좋은 결과를 얻었다고 다른 기관에서도 같다고 주장할 수 없습니다. 환경별 분리 평가, 관찰 모드의 오탐 표본 검토, 운영 데이터 이동에 따른 성능 변화 점검이 필요합니다.
