FIELD GUIDE · 03

제로 트러스트를 점검표로 바꾸기

2026-10-28 · 설계 검토용 예제

‘사내 네트워크에 있다’는 이유만으로 문서 열람을 허용하면 탈취된 계정이나 침해된 내부 장치에 과도한 신뢰를 줄 수 있습니다. 보호할 자원과 행위를 먼저 정의하고, 허용에 필요한 증거를 분리합니다.

교육용 접근 정책

자원은 finance-report, 행위는 read입니다. 인증 사용자, 재무팀 소속, 관리 기기, 5분 이내 확인된 기기 상태를 모두 요구합니다. 5분은 실습 가정이며 보편적인 표준 수치가 아닙니다.

인증 기록 누락거부신원 미확인

다른 팀의 쓰기 요청거부자원·행위 범위 외

실제 시스템에서 꼭 나눌 지점

정책 결정 지점이 ‘거부’를 반환해도 API에서 그 결과를 집행하지 않으면 접근이 허용될 수 있습니다. 브라우저, 직접 API 호출, 배치 내보내기, 캐시 경로의 동일 집행 여부를 따로 테스트합니다. 비상 계정과 장애 시 우회 절차도 감사 대상입니다.

검증 절차

  1. 자원·행위 목록을 확정합니다.
  2. 신원·기기 속성이 신뢰된 발급자로부터 왔는지 검증합니다.
  3. 누락·유효기간 만료·불일치 조건을 부정 테스트에 포함합니다.
  4. 결정 로그와 실제 리소스 응답을 비교해 정책 집행 여부를 확인합니다.
  5. 권한 회수 뒤 재요청·장시간 세션의 캐시 동작을 시험합니다.

근거: NIST SP 800-207 Zero Trust Architecture. 이 글은 표준 전체를 구현한 결과가 아니라 점검 관점을 설명하는 교육용 안내입니다.
